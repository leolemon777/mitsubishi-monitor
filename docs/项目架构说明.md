# MitsubishiMonitor.Demo 当前架构说明

> 本文描述 2026-08-29 对抗性整改后的现行源码。历史设计与过期代码片段见“项目架构深度分析-完整版”，运行边界以本文、`AGENTS.md` 和源码为准。

## 1. 项目定位与技术栈

这是一个 .NET 8 WPF 工业监控程序，通过 HslCommunication 的 `MelsecA1ENet`（MC 协议 1E 帧）监控 4 台三菱 FX3U PLC。界面采用 CommunityToolkit.Mvvm，曲线采用 LiveCharts2，数据由 EF Core 8 写入 SQLite，Excel 由 ClosedXML 导出。

主界面显示后会顺序探测所有已启用设备。四台设备分别持久化 `AutoStandby`、`RequiredOnline` 或 `Disabled` 运行模式，默认 `AutoStandby` 适配设备独立、随机开关机。`--demo-video` 是唯一演示入口；演示模式使用隔离的临时数据库，不读取或覆盖生产数据，也不会建立 PLC 或串口连接。

## 2. 数据流与生命周期

```text
PLC (TCP/MC 1E)
  -> MitsubishiPlcService（每设备一个会话、采集与恢复状态机）
  -> DeviceManagerService（4 台设备编排、健康/报警/塔灯策略）
  -> DeviceListViewModel / DeviceDetailViewModel
  -> MainWindow / DeviceDetailWindow

StateChanged / TemperatureSampled
  -> LogBufferService（有界内存队列 + JSONL 持久重放）
  -> DataService / MonitorDbContext
  -> SQLite

查询/导出
  -> DataService（稳定分页、计数与 SQL 聚合）
  -> BoundedLogExportLoader（总计 100,000 条上限）
  -> ExcelExportService（XLSX/CSV/HTML，临时文件原子落盘）
```

`App` 负责单实例保护、配置加载与演示模式隔离。主窗口创建唯一的 `DeviceListViewModel`，其内部创建唯一的 `DeviceManagerService`；详情窗口始终复用这一管理器，不会再创建第二组 PLC 会话或定时器。关闭程序时会取消启动任务、停止采集、冲刷日志并释放塔灯串口。

## 3. 核心模块

| 模块 | 当前职责 |
|---|---|
| `AppConfig` | 严格校验 4 个 IPv4 地址、重复地址、阈值、设备运行模式与绝对路径；原子保存并保留最近有效备份；旧配置缺少模式时迁移为四台自动待机 |
| `MitsubishiPlcService` | 连接代际隔离、X/Y/M 与温度/辅助量采集、首帧基线、单调时钟新鲜度、超时与熔断、事件订阅者隔离 |
| `DeviceMonitoringPolicy` | 将自动待机、要求在线、停用映射为连接授权、故障语义、塔灯参与范围与 30 秒/5 秒起步的退避节奏 |
| `DeviceManagerService` | 创建 4 台设备、按模式进行发现/重连编排、Fresh/Stale/Standby/Disabled/CommunicationFault 状态、温度报警、存储健康与塔灯策略 |
| `TowerLightPolicy` | 关机的自动待机设备和停用设备不参与；要求在线设备始终参与；已在线设备全部新鲜为绿、过期/故障为黄、活动超温为红 |
| `LogBufferService` | 3 秒批量写库；队列满或写库失败时写入 JSONL spool，成功后确认删除；坏记录进入 dead-letter 并上报健康故障 |
| `DataService` | 按数据库绝对路径初始化；版本化事务迁移；取消令牌；带 Id 次排序的稳定分页；全设备总数与区间统计；15 天保留期 |
| `AutoExportService` | 有界批处理、失败重排队和丢弃/失败健康状态，不静默丢数据 |
| `ExcelExportService` | ClosedXML 导出；后台生成、取消、公式注入防护、HTML 编码、唯一目录和原子提交 |
| `SafeEventDispatcher` | 单个订阅者异常不会阻断其他订阅者，也不会破坏采集循环 |

## 4. 状态与报警语义

`DeviceRuntimeState` 区分 `Disconnected`、`Standby`、`Disabled`、`Connecting`、`Reconnecting`、`OnlineFresh`、`OnlineStale`、`CommunicationFault` 和 `Demo`。`IsConnected` 只代表传输连接，不能替代样本新鲜度；主界面和塔灯同时依据运行模式与数据新鲜度。

自动待机设备离线时不是故障；软件保留最后有效值用于诊断，但主温度只显示 `--.-°C`。设备重新开机并通过 MC 只读验证后，只有当前连接代次取得新温度样本才恢复实时数值。要求在线设备离线才进入 `OfflineDevices` 和通信故障提示。

温度样本和热电偶辅助样本分别带时间戳。辅助量只有整组读取成功才原子提交，SSR 判断只使用仍新鲜的辅助数据。温度报警阈值与 PLC 目标温度是两个独立字段，数据库迁移会保留旧数据并补齐新列。

## 5. 查询、统计与导出

- 日志页“全部设备”按全局时间排序分页，不再给每台设备分配固定配额。
- 总数来自数据库 count；温度统计由 SQL 在完整区间聚合，图表只加载最近 50 个点。
- 关键词和日志类型是对当前已加载页的界面筛选，界面会明确提示这一范围。
- 导出先计数、再稳定分页加载；超过 100,000 条会明确拒绝，不会静默截断。
- 结束日期覆盖选择日全天；选择今天时上限为当前时刻。

## 6. 配置与现场边界

PLC 点位映射仍由代码定义；IP、报警阈值、每台设备运行模式、数据库路径和自动导出路径由 `config.json` 校验和持久化。设备模式与自动导出设置即时生效；数据库路径变更在下次启动生效，避免运行中同时写入两个数据库。

本轮自动验证只覆盖源码、数据库迁移、恢复状态机、策略和导出。它不启动 HMI，不连接真实 PLC/无线网桥/USB 塔灯，也不替代现场联调、断网恢复和硬件安全验收。
