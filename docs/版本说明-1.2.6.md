# MitsubishiMonitor 1.2.6

本版本修复全项目审查确认的 8 项问题：

1. 日志批次先写入磁盘 spool，数据库提交成功后再确认删除；正常退出时保存待写队列和迟到日志，并限制等待 SQLite 的时间。
2. 三色灯测试命令使原灯态缓存失效；恢复灯色和蜂鸣器时使用完整、串行的状态提交。
3. 批量连接使用每台设备的策略版本；停用设备后，旧任务不能再次启动它的采集。
4. 辅助轮读取完成后使用当前主温度计算报警，避免旧温度覆盖新报警。
5. 数据库初始化失败后自动退避重试，恢复成功后重新开启日志落库。
6. 配置备份只接受通过语义校验的内容；损坏的主配置不再覆盖有效备份。
7. 温度、电压和时间标签共用同一采样窗口，统一处理历史加载、实时追加和滚动。
8. 过期或缺失的辅助数据不再参与加热诊断；日志界面、Excel、CSV 和 HTML 导出保留辅助采样时间及质量。

## 使用变化

- 自动温度导出文件名为 `yyyy-MM-dd_温度记录_含采样质量.html`。旧格式文件保留，操作日志命名不变。
- “今日”图表保持实时跟随；本周、本月和全部显示所选历史范围。
- 配置字段和数据库 SchemaVersion 保持兼容。升级前保留原来的配置、数据库、Spool 和日志；不要在程序运行时复制 SQLite 数据文件。
- spool 保持提交后确认的回放语义；本版本不保证跨 SQLite 和文件的 exactly-once，异常终止发生在提交与确认之间时仍可能重放。

## 软件验证与部署

修复代码已在 Windows 执行机完成 Debug、Release 构建，均为 0 警告、0 错误；两个配置各 103/103 测试通过，其中新增 30 项回归用例。隔离的主窗口、设备详情、设置和日志查询加载检查通过。

正式发布使用应用项目 `MitsubishiMonitor.Demo.csproj`，输出为 Windows x64 自包含单文件程序，不能发布整个解决方案以免混入测试产物。发布包的实际提交号、构建环境、校验值与发布验证结果记录在包内 `PACKAGE-MANIFEST.json`。

真实 PLC、无线网桥、点位比例、三色灯和长时间运行测试留待现场进行；软件构建与隔离 UI 检查不等于现场验收。
